# Revisão de código: `notas.py`

Encontrei **1 defeito funcional**. Também registro **2 observações** que dependem de como o requisito é interpretado. Elas não são defeitos certos.

## Defeito 1: nota `NaN` é aceita como válida

**(1) Localização:** `Turma._validar_nota`, usada por `lancar_nota` e `lancar_exame`.

```python
if nota < 0 or nota > 10:
    raise NotaInvalidaError("nota fora do intervalo")
```

**(2) Problema:** `float("nan")` é do tipo `float` e passa pela verificação de tipo. Toda comparação com `NaN` retorna `False`, então `nan < 0 or nan > 10` é `False` e a nota é aceita.

**(3) Justificativa:** A RN03 exige nota "entre 0 e 10, inclusive", com `NotaInvalidaError` fora desse intervalo. `NaN` não está no intervalo [0, 10] e deveria ser rejeitada. Consequências observáveis:
- `lancar_nota(m, "P1", float("nan"))` não lança exceção.
- `media(m)` passa a retornar `nan`.
- Em `situacao`, `nan >= 7.0` e `nan < 5.0` são falsos. Um aluno com frequência suficiente cai em `"Exame"` (RN06 item 5), mesmo sem ter média entre 5,0 e 7,0.
- Com exame lançado, `media_final` também é `nan` e o resultado é `"Reprovado"`.
- `ranking()` passa a ter ordenação inconsistente, porque `-nan` não tem ordem definida. Isso viola a RN09.
- `lancar_exame(m, float("nan"))` também é aceito, o que viola a RN07.

Para comparação, `registrar_frequencia` já rejeita `NaN` corretamente. Ela usa `not 0 <= percentual <= 100`, que resulta em `True` para `NaN`.

**(4) Correção:** escrever a condição na forma positiva, como já é feito na frequência:

```python
def _validar_nota(self, nota):
    if isinstance(nota, bool) or not isinstance(nota, (int, float)):
        raise TypeError("nota deve ser numérica")
    if not (0 <= nota <= 10):
        raise NotaInvalidaError("nota fora do intervalo")
```

## Observações (não são defeitos certos)

**O1: tipos numéricos como `Decimal` e `Fraction` são rejeitados com `TypeError`** (`_validar_nota`).
A RN03 diz apenas "a nota deve ser numérica". `Decimal("7.5")` e `Fraction(15, 2)` são numéricos, mas o código os rejeita. Se a intenção for aceitar qualquer número real, a correção é usar `isinstance(nota, numbers.Real)`, mantendo a exclusão de `bool`. Se a intenção for aceitar só `int` e `float`, o código está correto.

**O2: modo de arredondamento** (`media` e `media_final`).
A função `round()` arredonda o valor binário real, e empates exatos vão para o número par. Exemplos:
- `round(5.625, 2)` resulta em `5.62`.
- `media = 5.00` com `exame = 4.99` dá `4.995`, que é armazenado como 4.99499…, e `round` resulta em `4.99`. A situação final fica `"Reprovado"`. Com arredondamento "meio para cima", o resultado seria `5.0` e a situação seria `"Aprovado"`.

As RN05 e RN08 dizem apenas "arredondado para 2 casas", sem definir o modo. Por isso não classifico isso como defeito. Se o modo esperado for "meio para cima", use `Decimal(str(valor)).quantize(Decimal("0.01"), ROUND_HALF_UP)`.
