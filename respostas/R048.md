# Revisão de código: `reservas.py`

Encontrei **3 defeitos funcionais**. Dois deles estão no mesmo método (`_conflita`).

## Defeito 1: falta validar o limite de participantes pela capacidade da sala

**(1) Localização:** `SistemaReservas._validar`, na verificação de `participantes`.

**(2) Problema:** o código verifica só o mínimo (`participantes < 1`). Não verifica se o número ultrapassa a capacidade da sala.

**(3) Justificativa:** a RR03 exige que o número de participantes seja "no mínimo 1 e no máximo a capacidade da sala". Hoje, uma sala de capacidade 5 aceita uma reserva com 50 participantes, quando deveria lançar `ReservaInvalidaError`.

**(4) Correção:**
```python
if participantes < 1 or participantes > self._salas[sala]:
    raise ReservaInvalidaError("número de participantes inválido")
```
A existência da sala já foi validada antes, então `self._salas[sala]` é seguro.

## Defeito 2: reservas encostadas são tratadas como conflito

**(1) Localização:** `SistemaReservas._conflita`, na condição `if inicio <= r.fim and fim >= r.inicio:`.

**(2) Problema:** a comparação usa `<=` e `>=`, ou seja, trata os intervalos como fechados.

**(3) Justificativa:** os requisitos definem os intervalos como semiabertos `[início, fim)`. A RR04 diz que "se uma termina às 10, outra pode começar às 10". Com o código atual, existindo a reserva [8, 10), uma nova [10, 12) dá `10 <= 10 and 12 >= 8`, que é verdadeiro, e lança `ConflitoDeHorarioError` indevidamente. O mesmo vale no sentido inverso (nova [6..8) não é possível por causa do horário, mas [12, 14) contra uma reserva existente [14, 16) também conflita).

**(4) Correção:**
```python
if inicio < r.fim and fim > r.inicio:
```

## Defeito 3: reservas canceladas continuam bloqueando o horário

**(1) Localização:** `SistemaReservas._conflita`, no laço `for r in self._reservas.values():`.

**(2) Problema:** o laço percorre todas as reservas, inclusive as canceladas, sem checar `r.ativa`.

**(3) Justificativa:** a RR04 restringe o conflito a "duas reservas **ativas**". A RR05 diz que a reserva cancelada "libera o horário para novas reservas". Com o código atual, depois de cancelar uma reserva [10, 12), uma nova reserva [10, 12) na mesma sala e data ainda lança `ConflitoDeHorarioError`.

**(4) Correção:**
```python
for r in self._reservas.values():
    if r.ativa and r.sala == sala and r.data == data:
        if inicio < r.fim and fim > r.inicio:
            return True
```
Essa versão corrige os defeitos 2 e 3 juntos.

## Itens verificados sem defeito

- **RR01:** valida capacidade ≥ 1 com `ValueError`.
- **RR02:** IDs sequenciais a partir de 1. O contador só avança quando a reserva é criada com sucesso.
- **RR03:**
  - Sala, data (`date` e ≥ hoje) e tipo inteiro dos horários estão corretos.
  - Horário de funcionamento 8–22, `inicio < fim` e duração ≤ 4 estão corretos.
  - O responsável é validado e salvo com `strip()`.
- **RR05 e RR06:** as exceções de `cancelar` e `buscar` estão corretas.
- **RR07:** `listar` filtra as reservas ativas e ordena por início.
- **RR08:** `range(8, 22)` produz as horas 8 a 21. As horas ocupadas usam `range(inicio, fim)`, o que respeita o intervalo semiaberto. Sala inexistente lança a exceção exigida.
- **RR09:** a base é de 14 horas e o arredondamento é de 1 casa. Nenhum valor k/14·100 cai exatamente em um empate de arredondamento, então o `round` se comporta como esperado.
