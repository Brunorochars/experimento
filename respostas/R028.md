# Revisão de Código: `reservas.py`

Encontrei **3 defeitos funcionais**. Todos estão em `_validar` e `_conflita`. Os demais métodos estão de acordo com os requisitos.

---

## Defeito 1: Não verifica se os participantes cabem na sala

**(1) Localização:** `SistemaReservas._validar`, na linha `if participantes < 1:`.

**(2) Descrição:** O código só verifica o limite mínimo de participantes. Não há verificação do limite máximo, que é a capacidade da sala.

**(3) Justificativa:** O RR03 diz que "o número de participantes deve ser no mínimo 1 **e no máximo a capacidade da sala**". Hoje uma chamada como `reservar("A", d, 10, 12, 50, "Ana")` em uma sala de capacidade 10 é aceita, quando deveria lançar `ReservaInvalidaError`.

**(4) Correção:**
```python
if participantes < 1 or participantes > self._salas[sala]:
    raise ReservaInvalidaError("número de participantes inválido")
```
Essa verificação é segura porque a existência da sala já foi validada antes.

---

## Defeito 2: Reservas encostadas são tratadas como conflito

**(1) Localização:** `SistemaReservas._conflita`, na linha `if inicio <= r.fim and fim >= r.inicio:`.

**(2) Descrição:** A condição usa comparações não estritas (`<=` e `>=`). Por isso, intervalos que apenas se tocam nas extremidades são considerados sobrepostos.

**(3) Justificativa:** O enunciado define os intervalos como semiabertos, `[inicio, fim)`. O RR04 diz explicitamente que "se uma termina às 10, outra pode começar às 10". Com o código atual, se existe a reserva [8, 10), uma nova reserva [10, 12) gera a avaliação `10 <= 10 and 12 >= 8`, que resulta em `True`. Assim, `ConflitoDeHorarioError` é lançado indevidamente.

**(4) Correção:**
```python
if inicio < r.fim and fim > r.inicio:
    return True
```

---

## Defeito 3: Reservas canceladas continuam bloqueando o horário

**(1) Localização:** `SistemaReservas._conflita`, na linha `if r.sala == sala and r.data == data:`.

**(2) Descrição:** O laço percorre todas as reservas, inclusive as canceladas. O atributo `r.ativa` não é verificado.

**(3) Justificativa:**
- O RR04 restringe o conflito a "duas reservas **ativas**".
- O RR05 diz que a reserva cancelada "libera o horário para novas reservas".

Hoje, depois de `cancelar(id)`, uma tentativa de reservar o mesmo horário ainda lança `ConflitoDeHorarioError`. Há também uma inconsistência interna: `horarios_livres` mostra o horário como livre, porque usa `listar`, que filtra as ativas, mas `reservar` o recusa.

**(4) Correção:**
```python
def _conflita(self, sala, data, inicio, fim):
    for r in self._reservas.values():
        if r.ativa and r.sala == sala and r.data == data:
            if inicio < r.fim and fim > r.inicio:
                return True
    return False
```
Outra opção é reaproveitar `self.listar(sala, data)`, que já filtra as reservas ativas daquela sala e data.
