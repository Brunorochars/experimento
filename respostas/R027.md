# Revisão de código: `carrinho.py`

## Conclusão

**Não encontrei defeitos funcionais.** O código atende aos requisitos RC01 a RC13 como estão escritos.

## Verificação por requisito

| Req. | Trecho | Situação |
|---|---|---|
| RC01 | `Produto.__init__` | Rejeita `preco <= 0` e `estoque < 0` com `ValueError`. |
| RC02 | `Carrinho.__init__` | O catálogo é indexado por código. O carrinho começa com `_itens = {}` e `_cupom = None`. |
| RC03 | `adicionar` | Valida a existência do código (`ProdutoInexistenteError`). Rejeita `bool` e tipos não inteiros (`TypeError`) e valores `< 1` (`ValueError`). Soma a quantidade nova à que já existe. |
| RC04 | `adicionar` | Compara `atual + quantidade` com o estoque e lança a exceção **antes** de alterar `_itens`. O carrinho não muda. |
| RC05 | `remover` | Valida a presença no carrinho. Sem quantidade, remove o item inteiro. Com quantidade, exige que esteja em `[1, qtd_no_carrinho]`. Quando o restante é 0, o item é removido. |
| RC06 | `itens` | `dict(self._itens)` devolve uma cópia. Como as chaves e os valores são imutáveis, a cópia rasa basta. |
| RC07 | `subtotal` | Soma `preço × quantidade`. |
| RC08 | `percentual_desconto` | Faixas `>= 500` → 10, `>= 200` → 5, senão 0. As fronteiras estão corretas. |
| RC09 | `aplicar_cupom` | Aplica `strip().upper()` e valida contra `{"DESC20", "FRETEGRATIS"}`. Um novo cupom sobrescreve o anterior. |
| RC10 | `total` | Abate R$ 20 depois do desconto progressivo. A condição usa o **subtotal** `>= 100`, como pede o requisito. |
| RC11 | `_frete` | O frete é zero com `FRETEGRATIS` ou quando o valor após os descontos é `>= 300`. Nos demais casos, R$ 25. |
| RC12 | `total` | Carrinho vazio retorna 0. `max(valor, 0.0)` impede valor negativo antes do frete. O resultado é arredondado para 2 casas. |
| RC13 | `finalizar` | Lança `CarrinhoVazioError` se vazio. Calcula o total **antes** de esvaziar, baixa o estoque, limpa os itens e o cupom e retorna o total. |

## Observações (não são defeitos pelos requisitos declarados)

1. **Arredondamento do subtotal** (`subtotal`, linha `return round(total, 2)`): os requisitos só exigem arredondar o **total**. Arredondar também o subtotal só mudaria algo com preços de mais de 2 casas decimais. Por exemplo, um subtotal de 499,996 viraria 500,00 e receberia 10% de desconto. Com valores em reais de 2 casas, o efeito é corrigir ruído de ponto flutuante, o que ajuda. Se a intenção for seguir o RC07 literalmente, basta remover o `round` de `subtotal()`.

2. **Estoque compartilhado entre carrinhos** (`finalizar`): os objetos `Produto` são compartilhados por referência. Se dois carrinhos usam o mesmo catálogo e os dois finalizam, o estoque pode ficar negativo, porque `finalizar` não revalida o estoque. Os requisitos não exigem essa revalidação, então não conta como defeito. Vale avaliar se o sistema terá múltiplos carrinhos.

3. **Entradas não especificadas**: os requisitos não definem o comportamento nestes casos, então não há violação:
   - `aplicar_cupom` com valor que não é string lança `AttributeError`.
   - `remover` com `quantidade` não inteira (ex.: `1.5`) é aceita.
   - Em `adicionar`, se o código e a quantidade forem ambos inválidos, prevalece `ProdutoInexistenteError`.
