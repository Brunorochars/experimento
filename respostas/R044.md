## Problema encontrado

### 1. `NaN` passa pela validação de valor (RB02, RB03, RB06)

**(1) Localização:** `Conta._validar_valor`, na linha `if valor <= 0:`. O efeito se propaga para `depositar`, `sacar` e `transferir`.

**(2) Descrição:** `float("nan")` é aceito como valor válido. Assim, um depósito, saque ou transferência com `NaN` é concluído. O saldo vira `nan`, e o mesmo acontece com `_sacado_hoje` no caso de débitos. A operação também é registrada no extrato.

**(3) Justificativa:**
- O RB02 exige que o valor seja "maior que zero", senão `ValueError`. `NaN` não é maior que zero.
- O código, porém, testa `valor <= 0`, e qualquer comparação com `NaN` retorna `False`, então nenhuma exceção é lançada.
- No débito, `valor > self._saldo` e `self._sacado_hoje + valor > LIMITE_DIARIO_SAQUE` também retornam `False`. Por isso o saque passa por todas as verificações.
- Depois disso, a conta fica corrompida: todas as comparações seguintes envolvendo o saldo ou o limite diário deixam de funcionar. `Banco.saldo_total()` também passa a retornar `nan`.

**(4) Correção sugerida:** testar a condição positiva exigida pelo requisito, em vez da negativa:

```python
def _validar_valor(self, valor):
    if isinstance(valor, bool) or not isinstance(valor, (int, float)):
        raise TypeError("valor deve ser numérico")
    if not valor > 0:          # rejeita também NaN
        raise ValueError("valor deve ser positivo")
```

Se também se quiser rejeitar `inf`, pode-se usar `math.isfinite(valor)`. Isso, porém, vai além do que os requisitos declaram.
