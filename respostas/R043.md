# Revisão de código: `carrinho.py`

Encontrei **3 defeitos funcionais**. Também há 1 observação de menor gravidade.

---

## Defeito 1: `adicionar` aceita quantidade 0

**(1) Localização:** `Carrinho.adicionar`, na linha `if quantidade < 0:`

**(2) Problema:** a validação rejeita apenas valores negativos. Por isso, `quantidade = 0` é aceita.

**(3) Justificativa:** o RC03 exige que a quantidade seja "maior ou igual a 1 (`ValueError`)". Com o código atual, `adicionar("X", 0)` não lança exceção e cria a entrada `{"X": 0}` no carrinho. Isso traz efeitos colaterais:
- `itens()` passa a retornar um item com quantidade 0.
- O carrinho deixa de ser considerado vazio (`if not self._itens`). Assim, `finalizar()` não lança `CarrinhoVazioError` (RC13) e retorna total 25,00, porque o subtotal é 0 e o frete é cobrado.
- `total()` também retorna 25,00 em vez de 0 (RC12).

**(4) Correção:**
```python
if quantidade < 1:
    raise ValueError("quantidade inválida")
```

---

## Defeito 2: a verificação de estoque ignora a quantidade já presente no carrinho

**(1) Localização:** `Carrinho.adicionar`, na linha `if quantidade > produto.estoque:`

**(2) Problema:** o código compara com o estoque apenas a quantidade nova. A variável `atual` é calculada, mas não entra na verificação.

**(3) Justificativa:** o RC04 determina que "a quantidade total de um produto no carrinho (a que já estava mais a nova) não pode ser maior que o estoque". Exemplo com estoque 5: `adicionar("X", 3)` seguido de `adicionar("X", 3)` é aceito e deixa 6 unidades no carrinho. O correto seria lançar `EstoqueInsuficienteError` na segunda chamada, sem alterar o carrinho. Como consequência, `finalizar()` pode deixar o estoque negativo (5 − 6 = −1), o que viola o invariante do RC01.

**(4) Correção:**
```python
atual = self._itens.get(codigo, 0)
if atual + quantidade > produto.estoque:
    raise EstoqueInsuficienteError(f"estoque insuficiente para {codigo}")
self._itens[codigo] = atual + quantidade
```

## Defeito 3: o cupom DESC20 é aplicado antes do desconto progressivo

**(1) Localização:** `Carrinho.total`, na linha
`valor = (subtotal - desconto_cupom) * (1 - percentual / 100)`

**(2) Problema:** o código subtrai os R$ 20,00 do cupom antes de aplicar o percentual progressivo. Na prática, o percentual incide também sobre o abatimento do cupom.

**(3) Justificativa:**
- O RC10 diz que o DESC20 "abate R$ 20,00 do valor **depois** de aplicado o desconto progressivo".
- O RC12 define `total = subtotal − desconto progressivo − desconto do cupom + frete`, em que o desconto progressivo é calculado sobre o subtotal.

Exemplo com subtotal de R$ 500,00, desconto de 10% e cupom DESC20:
- **Especificado:** 500 − 50 − 20 = **R$ 430,00** (frete 0)
- **Código:** (500 − 20) × 0,90 = **R$ 432,00** (frete 0)

Com desconto de 5%, a diferença é de R$ 1,00. Essa diferença também pode alterar o valor comparado com o limite de frete grátis de R$ 300,00 (RC11).

**(4) Correção:**
```python
desconto_progressivo = subtotal * percentual / 100
valor = subtotal - desconto_progressivo - desconto_cupom
valor = max(valor, 0.0)
return round(valor + self._frete(valor), 2)
```

---

## Observação (baixa gravidade, não é defeito confirmado)

**`subtotal()` arredonda o resultado para 2 casas.** O RC07 define o subtotal apenas como "a soma de preço × quantidade", e os requisitos mencionam arredondamento somente para o **total**. Se algum preço tiver mais de 2 casas decimais, o arredondamento antecipado pode alterar o valor e até mudar a faixa de desconto (por exemplo, 499,996 vira 500,00 e passa a receber 10%). Com preços em centavos, o arredondamento apenas corrige ruído de ponto flutuante e não causa divergência. Avalie conforme o domínio dos preços do catálogo.
