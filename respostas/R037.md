# Revisão de código: `notas.py`

Encontrei **3 defeitos funcionais** e **1 observação** sobre robustez.

## Defeito 1: Pesos de P2 e T trocados

**(1) Localização:** constante `PESOS`, no início do módulo.
```python
PESOS = {"P1": 0.35, "P2": 0.30, "T": 0.35}
```

**(2) Descrição:** P2 tem peso 0,30 e T tem peso 0,35.

**(3) Justificativa:** A RN05 define P1 = 35%, P2 = 35% e T = 30%. Isso altera `media()` e, por consequência, `situacao()`, `media_final()`, `lancar_exame()` e `ranking()`. Exemplo: P1 = 0, P2 = 10, T = 0 deveria dar 3,5, mas o código retorna 3,0. Com P2 = 0, T = 10, deveria dar 3,0, mas retorna 3,5.

**(4) Correção:**
```python
PESOS = {"P1": 0.35, "P2": 0.35, "T": 0.30}
```

## Defeito 2: Falta o limite superior (10) na validação da nota

**(1) Localização:** `Turma._validar_nota`.
```python
if nota < 0:
    raise NotaInvalidaError("nota fora do intervalo")
```

**(2) Descrição:** Só o limite inferior é verificado. Notas maiores que 10 (por exemplo, 11 ou 100) são aceitas.

**(3) Justificativa:** A RN03 exige nota entre 0 e 10, inclusive, com `NotaInvalidaError` fora do intervalo. A RN07 aplica a mesma validação ao exame. Assim, `lancar_nota(m, "P1", 15)` e `lancar_exame(m, 12)` deveriam lançar `NotaInvalidaError`, mas são aceitos e distorcem média e situação.

**(4) Correção:**
```python
def _validar_nota(self, nota):
    if isinstance(nota, bool) or not isinstance(nota, (int, float)):
        raise TypeError("nota deve ser numérica")
    if not 0 <= nota <= 10:
        raise NotaInvalidaError("nota fora do intervalo")
```
A forma `not 0 <= nota <= 10` também rejeita `float("nan")` (ver Observação).

## Defeito 3: Frequência de exatamente 75% reprova por frequência

**(1) Localização:** `Turma.situacao`, segundo `if`.
```python
if aluno.frequencia <= FREQUENCIA_MINIMA:
    return "Reprovado por frequência"
```

**(2) Descrição:** O operador `<=` faz com que 75% resulte em `"Reprovado por frequência"`.

**(3) Justificativa:** A RN06, item 2, diz: "frequência menor que 75%" e "75% exatos não reprovam por frequência". Um aluno com 75% e média 8 deveria estar `"Aprovado"`, mas o código o reprova. O erro também impede o exame de alunos com 75% e média entre 5 e 7, pois `lancar_exame` passa a lançar `ExameNaoPermitidoError` (RN07).

**(4) Correção:**
```python
if aluno.frequencia < FREQUENCIA_MINIMA:
    return "Reprovado por frequência"
```

## Observação: valor `NaN` passa na validação da nota

Não é um defeito separado; a correção do Defeito 2 já resolve.

- **Localização:** `Turma._validar_nota`.
- **Descrição:** `float("nan")` é um `float` válido. Como `nan < 0` é `False`, a nota é aceita.
- **Justificativa:** NaN não está "entre 0 e 10, inclusive" (RN03), então deveria gerar `NotaInvalidaError`. Se aceito, torna `media()` igual a `nan`, e `situacao()` passa a retornar `"Exame"` indevidamente, pois todas as comparações com NaN são falsas.
- **Correção:** usar `if not 0 <= nota <= 10:`, como no Defeito 2.
