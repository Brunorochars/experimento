# Revisão de código: `banco.py`

Encontrei **3 defeitos funcionais**. Também registro uma observação de robustez no final.

---

## Defeito 1: saque de todo o saldo é recusado

**(1) Localização:** `Conta._validar_debito`, linha `if valor >= self._saldo:`

**(2) Descrição:** O sistema lança `SaldoInsuficienteError` quando o valor é **igual** ao saldo. Isso impede que a conta fique com saldo exatamente zero.

**(3) Justificativa:** A RB03 diz que o saque é permitido quando o valor é **menor ou igual** ao saldo e que a conta pode ficar com saldo exatamente zero. O erro só deve ocorrer se o valor for **maior** que o saldo. Exemplo: uma conta com saldo 100 que chama `sacar(100)` recebe `SaldoInsuficienteError`, mas o esperado é sucesso com saldo 0. O mesmo defeito atinge `transferir`, que usa a mesma validação (RB06).

**(4) Correção:**
```python
if valor > self._saldo:
    raise SaldoInsuficienteError("saldo insuficiente")
```

## Defeito 2: transferência enviada não entra no total debitado do dia

**(1) Localização:** `Conta.transferir`, no bloco executado após `self._validar_debito(valor)`

**(2) Descrição:** A transferência bem-sucedida reduz o saldo da origem, mas não soma o valor em `self._sacado_hoje`.

**(3) Justificativa:** A RB04 diz que o limite diário considera **saques e transferências enviadas**. A RB06 diz que, em caso de sucesso, o valor "é somado ao total debitado no dia da origem". Com o código atual, uma conta pode transferir valores ilimitados por dia. Exemplo: duas transferências de R$ 800 no mesmo dia são aceitas, mas a segunda deveria lançar `LimiteDiarioError`. Além disso, um saque feito depois dessas transferências não as leva em conta.

**(4) Correção:**
```python
self._validar_debito(valor)
self._saldo = round(self._saldo - valor, 2)
self._sacado_hoje = round(self._sacado_hoje + valor, 2)
destino._saldo = round(destino._saldo + valor, 2)
self._extrato.append(("transferencia_enviada", valor))
destino._extrato.append(("transferencia_recebida", valor))
```

## Defeito 3: rendimento calculado com divisor errado

**(1) Localização:** `Conta.aplicar_rendimento`, linha `rendimento = round(self._saldo * taxa_percentual / 10, 2)`

**(2) Descrição:** O código divide por 10 em vez de 100. Por isso, o rendimento fica 10 vezes maior que o especificado.

**(3) Justificativa:** A RB07 define o rendimento como `saldo × taxa_percentual / 100`. Exemplo: com saldo 1000 e taxa 1, o código produz rendimento 100.0, mas o esperado é 10.0. O erro afeta o saldo, o registro no extrato e o valor retornado.

**(4) Correção:**
```python
rendimento = round(self._saldo * taxa_percentual / 100, 2)
```

## Observação (risco, não defeito confirmado)

**Localização:** `_validar_debito`, linha `if self._sacado_hoje + valor > LIMITE_DIARIO_SAQUE:`

A soma é feita em ponto flutuante sem arredondamento antes da comparação. Em alguns casos, o resultado pode ficar levemente acima de 1000.00 por erro de representação, mesmo quando a soma matemática é exatamente 1000.00. Isso recusaria indevidamente um débito que a RB04 permite ("é permitido atingir exatamente esse valor"). Para eliminar esse risco, use:

```python
if round(self._sacado_hoje + valor, 2) > LIMITE_DIARIO_SAQUE:
```

## Itens verificados sem defeito

- **Criação da conta (RB01):** validação do titular, remoção de espaços, recusa de saldo negativo e arredondamento do saldo inicial estão corretos.
- **Validação de valores (RB02):** `TypeError` para tipos não numéricos e booleanos, e `ValueError` para valores ≤ 0, estão corretos.
- **Taxa de rendimento (RB07):** a validação de tipo e do intervalo [0, 2] está correta, e o rendimento só é registrado quando é maior que zero.
- **Extrato e dia (RB08 e RB09):** `extrato()` retorna uma cópia e `novo_dia()` zera o total debitado.
- **Banco (RB10 a RB14):** a numeração sequencial a partir de 1001, `buscar` com `ContaInexistenteError`, `transferir`, `encerrar_dia` e `saldo_total` estão corretos. Uma transferência entre o mesmo número de conta lança `ValueError`, pois `destino is self`.
- **Transferência recusada (RB06):** as validações ocorrem antes de qualquer alteração, então nenhuma conta é modificada quando a transferência é recusada.
